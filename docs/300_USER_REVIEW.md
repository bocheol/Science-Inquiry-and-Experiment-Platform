# 약 300명 운영 및 30–60명 동시 사용 점검

이번 조사는 소스와 분리된 합성 테스트를 기준으로 합니다. 실제 학생 데이터나 production 유료 AI 요청을 부하 시험하지 않았습니다.

| 항목 | 확인한 사실 | 전체 확대 전 남은 작업 |
|---|---|---|
| 인증 | bcrypt/JWT, 세션 버전·비활성·학년도 검사, 로그인 DB 제한 | 실기기 쿠키, 로그아웃, 최초 비밀번호 변경 왕복 |
| 동시 DB | 원격 pg Pool 최대 5/컨테이너, connect 10초·idle 30초 | Cloud Run 실제 concurrency/max instances×pool과 Cloud SQL connection 수 대조 |
| 대화 | messages(session_id,sequence) 인덱스, AI에 최근 15개 대화 제한 | UI 조회는 대화 전체가 커질 수 있음. 페이지네이션·응답 2MiB 초과 처리 필요 |
| AI 중복 | DB 자원 잠금·요청 해시·완료 결과 캐시·15분 lease | 분산 전체 동시 제한·타임아웃·유료 중복 발생 및 lease 만료 복구 실증 |
| AI timeout/retry | OpenAI SDK 기본 2회 retry 사용, 별도 명시적 짧은 timeout이 주요 경로에 없음 | 기능별 timeout·백오프·재시도 비용과 부분 성공 조정 |
| 크레딧 | 해당 원본에 학생 크레딧·원장 API 없음 | 학생별 서버 원장, 추가/초기화 관리자 감사, 예약/환급 원자성 |
| 월 예산 | 해당 원본에 월 $25 전체 API 상한 없음 | 서버 월 단위 USD 원장과 선예약. 프론트 숨김만으로 통제하지 않음 |
| 이미지 | 학생 일지 JPG/PNG/WebP, 서버 실제 bytes 검사, 5MB×5장, PostgreSQL BYTEA | 장기 DB·백업 용량 계획, 학생/교사 열람 권한과 보존 기간 확정 |
| PDF | 교사 시험 PDF 서버 생성. AI 코칭 PDF 업로드 없음 | 형식/용량/스캔·프롬프트 인젝션·파싱/보존 정책을 포함한 별도 서버 어댑터 |
| 로그 | audit_logs, openai_usage stdout, push 관련 DB/작업 로그 | 학생별 토큰·USD·요청 결과 영구 집계와 최소 PII, 보존/삭제 정책 |
| 오류/역할 | 기존 테스트 612개, 새 API 6개 포함 | staging에서 30·60명 부하와 수업 시간 복구 동작 |

## 로그 분리 목표

로그인 성공/실패, AI 요청/requestId, 토큰 및 비용 정산, 파일 저장 결과, 제출 snapshot ID, 교사 조작 actor, 오류 trace ID를 별도 사건으로 남깁니다. 현재 모든 범주가 완전한 영구 비용 원장으로 구현됐다는 뜻은 아닙니다. 비밀번호·쿠키·키·학생 대화 원문을 일반 운영 로그로 출력하지 않습니다.

## 비용 원장 구현 조건

- 월키와 예산 USD를 서버에서 결정하며 기본 상한 $25는 관리자가 설정합니다.
- 하나의 DB 거래에서 전역 월 잔액과 학생 크레딧을 잠그고 requestId별 최대 예상 비용을 예약합니다. 동시 60개 요청이 같은 잔액을 모두 통과하지 못해야 합니다.
- 모델·입출력 최대 토큰·웹검색/파일 비용을 서버에서 선택합니다. 최신 공식 가격표를 서버 버전 설정에 기록합니다.
- 성공은 실제 토큰/도구 사용량으로 정산하고 잔여 예약을 환급합니다. timeout/부분 성공은 공급자 요청 ID로 중복 청구를 대조합니다. 학생에게 비용을 추정값으로 확정 표시하지 않습니다.
- 월 경계, 초과, 중복 요청, 실패/예약 만료, 교사 초기화, 여러 컨테이너 동시 호출을 실제 PostgreSQL에서 시험한 뒤에만 AI 중계를 엽니다.

## 단계별 진입/복귀

1. Phase 1 교사: 합성 화면 + 독립 staging DB·서버. 로그인/강제 비밀번호 변경/자기 팀만 보기/다른 팀 거부/저장 충돌/일지/제출/만료 확인.
2. Phase 2 5–10명: 한정 계정, 유료 AI가 필요하면 위 서버 원장 완료가 선행. 초기 합성 기록과 실기록을 구분.
3. Phase 3 약 30명: 한 반 수업. 실패율·응답시간·DB 연결·AI 예약과 일지 크기를 기록하고 60개 동시 합성 부하.
4. Phase 4 약 300명: 교사 확인 후 확대. 기존 프론트 유지. 새 UI 문제 시 기존 화면으로 복귀하고 데이터는 같은 기존 서버에서 보존.
